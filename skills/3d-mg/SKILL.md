# 3D-MG 三维镜像治理法

## 这个技能信什么

1. **记录不是解释。** 财报能说清「毛利降了 1.2 个点」，但说不清这 1.2 个点里多少来自原材料、多少来自稼动率。**只做记录的分析不叫治理，叫记账。**
2. **口径先行，模型在后。** 口径没签署就建模型，建出来的一定是错的，而且错得看不出来——因为合计对不上时没人知道漏了什么。**口径确认单签字率不到 100%，不许动手。**
3. **数据不足不是不做的理由，但必须有标注。** 很多因果关系从来没有数据（没换过供应商，所以不知道换了好会怎样）。做法是结构化访谈 + 量级估计，并**明确标注「仅供讨论，不作决策依据」**，等两年数据验证后再升级。**既不假装有数据，也不干脆不做。**
4. **治理不是预测。** 预测给一个点值，治理给「关键变量的可控区间 + 触发阈值 + 动作」。产出「明年毛利率 18%」没有价值；产出「铜价季度均值超过 82,000 元/吨即启动报价联动 V2」才有价值。
5. **先找链路，别先找数据。** 从「去年最大的单项损失是什么」倒推，两小时能找出一条完整真实的因果链；从全流程顺推，两周都找不准。**这是本方法最高效的入口。**
6. **只做纠偏，不做追责。** 一旦这套东西被当成问责工具，业务部门会立刻开始做数据防御，第一次月度更新就会开始美化数据。**数据一旦不真，整个方法死亡。** 这是硬约束，不是软承诺。
7. **判断因果方向靠人，算弹性靠机器。** 相关性不能推出因果，因果方向必须由业务判断（来源人+ 日期要留痕）；弹性系数可以用回归估算。**方向错了，跑得再快也是错的。**
8. **不修正方向，只修正假设。** 3D-MG 修 MTP 的假设和节奏，不修战略方向和业务布局。越界会导致失去管理层信任。

## 什么时候用 / 不用

**用**：
- 经营出现偏差但说不清原因（「毛利降了」「成本涨了」「客户流失了」）
- 需要判断某个决策的代价（「年降 3% 接不接」「这个项目能不能投」「提价多少能保住毛利」）
- 目标定完不知道能不能达成（「明年目标 19% 倒推需要什么条件」）
- 需要事前预警而不是事后统计
- 要把老员工脑子里的隐性经验结构化沉淀
- 部门之间争议靠立场各让一步，需要数据裁决
- 集团与事业部之间共享资源分配公平性争议

**不用**：
- 纯财务合规、税务筹划、准则适用、内控审计
- 纯人事、组织行为、文化、激励
- 不可测变量主导的领域（品牌资产长期积累、国家政策远期走向）——只做定性情景，不做弹性系数
- 一次性重大并购（只做交易尽调，不纳入滚动治理模型）
- 研发技术方案选型（属技术评审，不属因果传导建模；研发投入的财务后果属模型，方案优劣不属）

## 开工前必须先确认的四件事

**不要接过来就建模。按顺序问清这四件事，缺一件就停下来要。**

| # | 要确认什么 | 为什么 | 问不出来怎么办 |
|---|---|---|---|
| 1 | **数据在哪** —— 现有的财报、ERP、经营台账都有什么 | 3D-MG 100% 复用现有数据，**一分额外采集都不要**。若发现要重新做账才能拿到数据，说明建法错了 | 停下来告诉用户：现有台账不支持这个分析，先补基础，暂不做 |
| 2 | **这次要回答什么经营问题** —— 具体到一个数字或一个决策 | 每个模型必须先写清「建成后谁做什么决策」。写不出就不建 | 反问用户：「建完这个模型，谁会因为它改变什么决策？」 |
| 3 | **口径谁说了算** —— 业务口径的定义权与签字人 | 口径不统一则合计对不上，模型不可用 | 要求用户指定口径签字人，否则不做 |
| 4 | **这次覆盖哪条链路** —— 一次只做一条 | 七个模型并行必然全部半成品 | 按 `references/models.md` 的 ABC 优先级打分选一条 |

## 三层镜像：核心工作流

```
现状镜像（事实层）→ 因果镜像（关系层）→ 推演镜像（选择层）
      ↑                ↑
   每月刷新          季度校准
                │
        用「现状＋因果」滚动修正 MTP ←──── 推演镜像
```

**三条硬约束：不可跳层、不可反向、不可固化。** 完整定义与执行步骤见 `references/methodology.md`。

| 层 | 回答 | 频率 | 一句话动作 |
|---|---|---|---|
| 现状镜像 | 现在到底发生了什么 | 每月 | 现有数据按「因果分组」重排，**不重做账** |
| 因果镜像 | 为什么会这样，谁在起作用 | 季度 | 建因果关系 + 估弹性系数 + 定阈值规则 |
| 推演镜像 | 如果这样变会怎样 | 半年 | 四情景构建 + 敏感性分析 |

## 工作模式选择（先判断走哪条路）

**模式一｜诊断（默认，最常用）**
用户说「毛利为什么降了」「这个数怎么来的」→ 直接进入现状镜像六步 + 因果定位。
完整步骤见 `references/methodology.md` 的「现状镜像六步」。

**模式二｜建模**
用户明确要求建某个传导模型 → 走五步法（定链路 → 画因果图 → 定口径 → 估弹性 → 定阈值）。
七项模型的公式、资料库、输出物、风险表见 `references/models.md`。

**模式三｜推演**
用户问「目标能不能达成」「A 方案值不值」→ 建四情景 + 敏感性分析。
方法见 `references/methodology.md` 的「推演镜像」节。

**模式四｜推行**
用户要推这套东西、准备汇报、做试点 → 读 `references/rollout.md`（含90 天日程、七道验收门、六条承诺、推广话术）。

**模式五｜出正式文档（报告 / HTML 汇报）**
用户要出正式交付物 → 读 `references/deliverable.md`（交付物清单、排版规范）。
**要出自适应 HTML 汇报文档 → 读 `references/report_format.md` + 跑 `scripts/gen_report_html.py`。**

## 自适应 HTML 汇报文档（交付物 5）

**双端自适应网页（默认路径，只需 Read + Write）**：窄屏（≤768px）竖向单列，宽屏（≥769px）横向两栏，
自带「强制横向 / 强制竖向 / 恢复自动」切换按钮，偏好记在 localStorage，顶部有实时视图状态。

做法：
1. **Read** `templates/report-template.html`（已内联全部 CSS/JS，零外部依赖）；
2. 把你的诊断报告整理成 `blocks` 数组（结构见 `references/report_format.md` 的 12 模块 + DSL）；
3. 将 `__REPORT_JSON__` 占位符替换为该 JSON，用 **Write** 另存为 `公司名_3D-MG.html` 即可直接打开/分享。

模板已内置降级：未填数据时显示版式示例，便于你对照结构。

（已启用 Bash · 可选路径）也可把报告先写成 DSL，再跑脚本：

```bash
python3 scripts/gen_report_html.py 报告.dsl -o 报告.html --title "示例公司（600000.SH）"
```

格式规范、12 个模块的标题与载体、通栏判定规则、十条交付前自检，
**全部以 `references/report_format.md` 为唯一权威定义**，不要自创结构。

> **写报告时必须同时遵守两条约束**：严禁编造精确数字，**但同样严禁用「未获取」逃避量化**。
> 只写前者，报告会变成一堆正确的废话；只写后者，模型会编。
> 正确做法：有把握的写数字并标年份；记不准的写「约」并降精度，**但方向与幅度仍要写**；
> 数字凑不齐就直说「数据不足，无法做归因校验」——**编造一个能凑平的算式是最严重的错误**。

## 五个交付红线

违反任意一条即为不合格，**不要交付，先返工**。

| # | 红线 | 检查方法 |
|---|---|---|
| 1 | **口径签字率 100%** | 未签署的口径确认单，数据一律不采用 |
| 2 | **三段归因合计误差 < 0.05pp** | 合计对不上说明有未纳入项，禁止定稿 |
| 3 | **归因必须量化到变量与幅度** | 「其他」「市场原因」「客观因素」**不是归因**，必须打回重写 |
| 4 | **因果图节点 ≤ 25、边 ≤ 40** | 超过说明建模范围失控，拆分或降级 |
| 5 | **每条关系有置信度标注** | 回归(R²)／专家估计·已验证／专家估计·待验证／背景参数，四选一，不可缺失 |

## 关键判断：链路找不到怎么办

**不要从全流程顺推找因果链**（研发→采购→生产→销售→售后），会陷入无限细节。用三个反推入口：

| 入口 | 反推问题 | 通常找到 |
|---|---|---|
| **钱入口** | 去年最大的单项损失是什么？ | 对应模型一／三／四 |
| **人入口** | 问资深员工：「你最担心的失控点是什么？」 | 通常直接指向模型六或二 |
| **变入口** | 最近三个月哪次决策让你最难受？ | 通常指向内部负外部性节点（⊙） |

**「钱入口」的完整示范**（约 2 小时走完）：

```
问：4,000 万毛利减少，首先哪个数字变了？
答：材料成本增加 1,900 万。
问：哪些物料涨的？
答：金属料 +1,500 万、树脂 +400 万。
问：金属料为什么涨？
答：两个原因——采购均价涨 12%，采购量增加 8%（用量没变，是备货）。
问：均价涨 12%，是否全部传导到当期成本？
答：不是。锁价比例 40%，当月只传导 60% × 70% ≈ 42%。
问：为什么不是全部？另外部分去哪了？
答：进了库存，在下期体现 → 存在时滞。
```

## 常见错误（这些是最常见的失败原因）

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 重做财报、重新盘点、要求基层重新填表 | 周期无限拉长，引发抵触 | 100% 复用现有台账；缺字段时只补「字段映射」不补「数据填报」 |
| 一次建七个模型 | 全部半成品，一年浪费 | 一次一条，90 天见效后再复制 |
| 只做现状镜像不做事后修正 | 变成一份更漂亮的经营报表 | 现状镜像的唯一用途是为因果模型提供基期，不是终点 |
| 把模型做成个人 KPI | 业务部门数据防御，模型失真 | 制度上明确不进考核；只做纠偏不做追责 |
| 因果方向靠相关性推断 | 方向错了跑得再快也错 | 因果方向必须业务判断，注明来源人与日期 |
| 只报数字不解释 | 管理层看不懂 = 没用 | 每个输出物必须能回答一个具体经营问题 |
| 建独立信息系统 | 重复投资，数据同步难持续 | 用现有 Excel + 现有 ERP／BI |
| 外部咨询独立完成建模 | 业务知识在内部，外部建模必错 | 内部主导，外部只做方法论陪跑 |
| **报告写成大段定性文字** | 没有说服力，管理层不看 | 按 12 模块格式，信息落进 KPI / 表格 / 链路 / 短判断 |

## 迭代机制（避免变成一次性工程）

| 版本 | 频次 | 人·天 | 覆盖 | 会改什么 |
|---|---|---|---|---|
| 首次搭建 | 一次性 | 15—20 | **只做 1 条链路** | 建模型 |
| 月度轻量更新 | 每月 | 1.35 | 已建模型 | **只刷指标**，不改口径/系数/因果/数据源，不开会 |
| 年度深度校准 | 每年 | 26 | 全部 + 新增建议 | 系数重估、失效关系清理、模型退役评估 |

**月度更新的四条禁止**：不改口径、不改系数、不重估因果、不新增数据源。月度出现「3D-MG 专项会」=前一版归因没做完，必须回退。

## 数据不够时的三级降级（务实设计）

| 级别 | 数据条件 | 方法 | 可用于决策？ | 标注 |
|---|---|---|---|---|
| 一级 | ≥24 个月连续数据 | 多元回归估弹性 | **可直接用** | 回归 R² + p 值 |
| 二级 | 12—24 个月或有缺失 | 回归 + 专家交叉验证 | 需业务确认 | 「部分估计」+ 来源 |
| 三级 | 无系统数据／从未单独观测 | 结构化访谈 + 量级估计 | **仅供讨论** | 「专家估计」+ 访谈日期 |

**量级转换规则**（访谈→可用数字）：几乎无影响→≤0.05（降级背景参数）；有点影响→0.1；影响较大→0.2；影响非常大→0.4；一变就全盘改变→≥0.6（必须数据验证后才可进决策）。

## 异常处理规则

1. **用户缺少目标企业财报/经营资料**：停止深度诊断，输出标准化资料清单，并说明资料缺失对结论可信度的影响（降到三级降级）；
2. **用户索要超出边界的投资评级**：拒绝，重复免责声明；
3. **用户要求修改 3D-MG 底层理论框架**：告知模型底层定义锁定（系统论／有限理性／闭环控制、三层镜像、七项专项模型），仅可调整案例对象与输出表现形式。

# 3D-MG 报告标准格式（12 模块）

> **本文件是输出格式的唯一权威定义。** 小程序（`utils/report-html.js`）与技能脚本
> （`scripts/gen_report_html.py`）都是本规范的实现，两边行为必须一致。
> 标准来源：`processed/__v2b_new.pdf`（宽屏版）与 `__v3b_new.pdf`（V3 手机竖版）——
> 同一份内容的两种版式，所以"双端自适应"是格式本身的要求，不是附加功能。

---

## 一、形态原则

1. **以卡片为基本单元**，每张卡片一个模块，模块顺序固定、标签照抄。
2. **信息必须落进载体，不写长段落**：
   - 单一关键数字 → `@KPI`
   - 多维对比 → `@TABLE`
   - 传导过程 → `@CHAIN`
   - 判断/警示 → `@NOTE`
   - 并列要点 → `@LI`
   - 段落 `@P` **每段 ≤60 字，全篇 ≤6 段**，只用来讲机制。
3. **表格 3—4 列**，最后一列写「关键含义 / 判定 / 建议动作」，
   不让读者自己从数字里猜结论。
4. **数字必须带单位与年份**（亿元 / 万辆 / % / pp；例：毛利率 11.8%（示例年度））。
5. **宁可少写，不要注水**。篇幅约 1200—1800 字，能进表格的不要写成段落。

## 二、行式 DSL（模型的输出格式）

每行一个动作，行首 `@`（大小写不敏感），字段用 `|` 分隔：

| 标记 | 含义 | 示例 |
|---|---|---|
| `@HERO` | 封面主标题 | `@HERO 示例公司（600000.SH） \| 核心痛点诊断与经营决策推演 \| 现状镜像 → 因果镜像 → 推演镜像` |
| `@CARD` | 开一张模块卡片 | `@CARD 财务事实 \| 费用结构是问题所在` |
| `@SUB` | 卡片副标题（1 行） | `@SUB 毛利额 vs 三项费用 —— 问题的总开关` |
| `@P` | 短段落 | `@P 不是「毛利不够」，是费用增速追不上毛利增速。` |
| `@KPI` | 大数字块 | `@KPI 4.5 亿 \| 经营缺口 \| 占归母亏损 70%` |
| `@TABLE` | 表头（后接 `@ROW`） | `@TABLE 指标 \| 2025 年 \| 同比 \| 关键含义` |
| `@ROW` | 表格数据行 | `@ROW 营业收入 \| 322.9 亿 \| +8.6% \| 结构升级拉高均价` |
| `@LI` | 列表项 | `@LI 判断1：毛利率改善追不上费用率上升` |
| `@CHAIN` | 因果链 | `@CHAIN 链① 销量失血 \| 销量 -3.1% → 固定成本无法摊薄 → 产能利用率 48%` |
| `@NOTE` | 关键判断 / 警示 | `@NOTE ★ \| 三项费用 42.6 亿 ＞ 毛利额 38.1 亿` |

**为什么不用 JSON**：JSON 在流式输出里半截就解析不了，中文引号转义也极易出错；
行式标记可以边生成边渲染，模型也更容易写对。

**解析器容错**（模型写歪时不丢内容）：
- 直接写 Markdown 表格（`| a | b |`，含跳过分隔行 `|---|---|`）→ 解析成表格
- 直接写 `## 标题` → 解析成卡片
- 未知 `@XXX` 标记 → 当段落处理

## 三、12 个固定模块

| # | 模块标签 | 卡片标题（可微调） | 主要载体 |
|---|---|---|---|
| 1 | — | `@HERO` 公司名（代码） | 主标题 + 副标题 + 三行说明 |
| 2 | `摘要` | 一句话结论与三大痛点 | 1 行 `@P` + **量化摘要表**（序｜痛点｜量级｜置信度，3—5 行）+ `@NOTE ★` |
| 3 | `财务事实` | 核心财务事实 | 2—3 个 `@KPI` + 指标表（指标｜本期｜同比｜关键含义，5—6 行） |
| 4 | `销量产能` | 销量、产能与结构 | `@KPI`（产能利用率）+ 行业对照表（板块｜本公司｜行业｜差距）+ 分项结构表 |
| 5 | `三段归因` | 账面亏损 ≠ 经营亏损 | 归因表（归因项｜金额｜说明）+ `@LI` 校验行 + 3 条 `@LI` 关键发现 |
| 6 | `因果链` | 外生冲击 → 失血链 → 断点 | 3 条 `@CHAIN` + `@NOTE ★ 断点` |
| 7 | `痛点①` | 优先级最高的痛点 | `@CHAIN` + 多期对比表（4 列）+ 3 条 `@LI` 判断 + `@NOTE` 弹性估算 |
| 8 | `痛点②` | 第二痛点 | 同上结构（可换多年份表） |
| 9 | `痛点③` | 第三痛点 | `@KPI` + `@CHAIN`（负反馈环）+ 正/负外部性与裁决层级表 + `@NOTE ★` |
| 10 | `推演镜像` | 目标反推与情景 | 目标反推表（条件｜需要什么｜现状｜判定）+ 情景表（情景｜关键假设｜结果方向）+ `@NOTE ★` |
| 11 | `优先级` | 敏感性与干预顺序 | 敏感性表（排序｜变量｜每变动影响｜可控性）+ P0—P2 表（优先级｜痛点｜难度·周期｜建议动作）+ `@LI` 干预逻辑 |
| 12 | `结论` | 必须说清的三句话 | 3 条 `@LI` + 方法论声明表（数据来源 / 置信度分级 / 升级建模还缺什么） |

**非上市公司**：第 3—5 个模块改为「经营规模」「业务与客户结构」「竞争位次」，
用公开可得的量级、增速、份额、融资与经营信号填充，并注明哪些属于推断。

## 四、三条不可让步的约束

1. **严禁编造精确数字 —— 但同样严禁用「未获取」逃避量化。** 两条一起成立：
   只写前者，模型会把所有数字写成"未获取"，报告变成一堆正确的废话；
   只写后者，模型会编。做法是：有把握的写数字并标年份；记不准的写「约」并降精度，
   **但方向与幅度仍要写**；只有确实一无所知才写「未获取」并说明缺哪一项。
2. **数字凑不齐就直说**「数据不足，无法做归因校验」——
   编造一个能凑平的算式是最严重的错误。
3. **对象类型不得推翻**：给了证券代码或用户选了「上市公司」，就按上市公司写。

## 五、通栏判定（宽屏布局）

宽屏（≥769px）下排两栏，但有的卡片天生该独占整行。判定规则（**集中在一处实现，
两端共用**）：

| 条件 | 是否通栏 |
|---|---|
| 封面 `@HERO` | 恒通栏 |
| 卡片含 ≥2 张表 | 通栏 |
| 某张表 ≥5 列 | 通栏 |
| 某张表 ≥8 行 | 通栏 |
| 含 `@CHAIN` | 通栏 |
| 标题命中 封面/摘要/总览/因果链/三段归因/结论/方法论/优先级/情景 | 通栏 |
| 其它（含 4 列表格） | **两栏** |

> ★ 阈值放宽过一轮：4 列表在半宽卡片里排得下，若 4 列就通栏，
> 真实报告会退化成"全宽单列"，分栏失去意义。**布局阈值必须用真实内容测。**

## 六、自适应 HTML 的硬性要求

| 项 | 要求 |
|---|---|
| 窄屏 `max-width:768px` | 竖向单列堆叠，KPI 两个一行 |
| 小屏 `max-width:480px` | 表格压紧（padding 6px 7px、字号 12px、表头允许换行），KPI 数值降到 20px |
| 宽屏 `min-width:769px` | 两栏 + 通栏卡片跨整行，KPI 四个一行 |
| 视图切换 | 三个按钮：强制横向 / 强制竖向 / 恢复自动 |
| 偏好记忆 | `localStorage`，键名 `3dmg_view_mode` |
| 状态提示 | 页面顶部实时文字：【当前视图：自动适配 / 强制横向（双栏）/ 强制竖向（单列）】 |
| 零外网依赖 | 不加载任何 CDN；Mermaid 为渐进增强，缺失时箭头链路卡照常显示 |
| 打印 | `@media print` 隐藏控制栏、去阴影、卡片不断页 |

**强制视图用 class 覆盖**（优先级高于媒体查询）：
`.force-landscape` / `.force-portrait` 加在容器上，用 `!important` 覆盖 flex 规则。

## 七、生成方式

```bash
# 从 DSL 生成自适应 HTML
python3 scripts/gen_report_html.py 输入.dsl -o 输出.html --title "示例公司（600000.SH）"

# 同时输出纯文本（表格按显示宽度对齐，可直接粘贴）
python3 scripts/gen_report_html.py 输入.dsl -o 输出.html --txt --stats
```

产出：
- `.html` —— 自包含，双击可开，手机窄屏 / 电脑宽屏自适应
- `.txt` —— 表格对齐的纯文本版（复制、粘贴、存档用）

## 八、交付前自检

| # | 检查项 | 不合格怎么办 |
|---|---|---|
| 1 | 12 个模块齐全、顺序正确、标签照抄 | 补模块，不许自创结构 |
| 2 | 摘要卡有量化排序表（序/痛点/量级/置信度） | 补表；没有量级的痛点删掉或降级 |
| 3 | 每条痛点的「症状」带数字 | 补数字；补不上就标「未获取」并说明缺什么 |
| 4 | 段落 ≤6 段、每段 ≤60 字 | 能进表格的改成表格 |
| 5 | 数字都带单位与年份 | 逐个补 |
| 6 | 有一张「关键含义 / 判定 / 建议动作」列 | 表格最后一列补上 |
| 7 | 有 ★ 断点或关键判断 | 补 `@NOTE ★` |
| 8 | 结论卡含方法论声明（数据来源 + 置信度分级） | 补 `@LI` 或声明表 |
| 9 | 上市状态与用户指定一致 | 改正；矛盾即返工 |
| 10 | 不构成投资建议的免责表述在位 | 补 |

> **示例数据说明**：本文所有 DSL 示例中的公司名与财务数字均为虚构示例，算术自洽可校验（示例公司：营收 322.9 亿 → 毛利率 11.8% → 毛利 38.1 亿；费用率 13.2% → 费用 42.6 亿 → 缺口 4.5 亿），不代表任何具体企业。

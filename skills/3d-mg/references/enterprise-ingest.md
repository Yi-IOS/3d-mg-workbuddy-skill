# 企业本地数据导入分析（私有数据）指南

> 本指南定义：当一家企业把本企业的私有资料（财务报表、审计报告、经营分析、中期事业计划 MTP 等）
> 放进本地目录后，如何用 3D-MG 像分析上市公司一样产出诊断报告。
> **核心原则：分析方法与上市公司诊断完全一致，唯一区别是数据来源由「模型公开知识」换成「企业本地文档」。**

---

## 一、适用场景

- 企业想把内部真实台账喂给 3D-MG，跑出比公开口径更细的诊断（到事业部 / 产品 / 客户）。
- 集团对子公司、事业部对自身做经营偏差归因，且资料不能外发。
- 已有年报/季报/审计报告/MTP，希望一键生成 12 模块结构化报告 + 自适应 HTML。

---

## 二、资料类型与目录约定（推荐）

在仓库内或用户指定路径下建 `data/` 目录，按类型分放：

```
data/
├── 01_财务报表/        # 资产负债表 / 利润表 / 现金流量表（年报、季报）
├── 02_审计报告/        # 审计报告、内控审计、附注
├── 03_经营分析/        # 经营分析月报、事业部复盘、产销存报表
├── 04_中期事业计划/    # MTP / 三年滚动规划 / 预算
└── 00_资料清单.md       # 按 templates/enterprise-data-manifest.md 登记
```

- 支持的格式：PDF / DOCX / XLSX / CSV / MD / TXT。模型用 **Read** 直接读，不要求统一格式。
- 一份资料可登记多期间（如 2023/2024/2025 三年利润表），便于做同比与趋势。

---

## 三、数据分层与复用原则（沿用 3D-MG 铁律）

| 原则 | 要求 |
|---|---|
| **100% 复用现有台账** | 不要求基层重做账、重新填表；缺字段只补「字段映射」不补「数据填报」 |
| **口径先行** | 内部口径定义权与签字人必须明确，口径确认单签字率 100% 才动手 |
| **只做纠偏不做追责** | 内部数据一旦用于问责会被美化，方法即死；制度上明确不进考核 |
| **数据不足要标注** | 缺某项就写「缺 X」，不编造；三级降级（见 SKILL.md）照常适用 |

---

## 四、导入四步（流程）

1. **建资料清单**：填 `templates/enterprise-data-manifest.md`，登记每份资料的
   类型 / 期间 / 路径 / 责任人 / 密级。模型据此判断覆盖哪条链路、缺什么。
2. **口径确认**：沿用「开工前四件事」——数据在哪、回答什么经营问题、口径谁签字、覆盖哪条链路。
3. **读资料 → 三层镜像**：
   - 现状镜像：用真实台账按「因果分组」重排，**不重做账**；
   - 因果镜像：建因果关系 + 估弹性（内部数据可做一级/二级回归）；
   - 推演镜像：用 MTP 做目标反推与四情景。
4. **导出报告**：同模式五，产出 12 模块报告 + 自适应 HTML（默认存本地）。

---

## 五、与上市公司分析的差异（对照）

| 维度 | 上市公司分析（公开知识） | 企业内数导入分析（私有数据） |
|---|---|---|
| 数据来源 | 模型训练知识（可能滞后） | 企业本地文档（最新、最细） |
| 对比基准 | 行业公开对标 | 企业自身历史 / 预算 / MTP |
| 颗粒度 | 公司级 | 事业部 / 产品 / 客户级 |
| 信息不足处理 | 拒绝或降精度 | 标注「缺 X」，走结构化访谈补 |
| 外发限制 | 可公开 | **必须脱敏后外发，默认仅本地** |

---

## 六、口径确认单（内部版 · 简表）

| # | 要确认什么 | 谁签字 |
|---|---|---|
| 1 | 本次分析覆盖哪条链路（一次一条） | 业务负责人 |
| 2 | 关键指标的计算口径与数据来源表 | 财务负责人 |
| 3 | 哪些结论可外发、哪些仅内部 | 授权人 |
| 4 | 缺项如何处理（标注 / 访谈补 / 暂缓） | 项目牵头人 |

---

## 七、保密与脱敏红线（最高优先级）

1. **全程本地**：资料读取、分析、报告生成均在本地完成，**不上传任何云端、不调用外部接口**。
2. **报告默认本地**：导出的 HTML / Word 默认存本地；外发前必须脱敏（隐去客户名、具体金额量级可用区间代替）。
3. **不写进会外传的位置**：内部数据不得进入任何可能被同步到公共仓库的字段。
4. **密级跟随**：资料清单里标「仅内部」的项，报告中一律不出现原值。

---

## 八、导出物

与模式五一致：12 模块标准报告（Markdown）+ 自适应横竖屏 HTML（Read 模板→填 `__REPORT_JSON__`→Write）。
如需 Word，跑 `scripts/gen_docx.py`（需 Bash）。

> **免责声明**：本报告基于企业提供的内部资料生成，仅用于该企业内部经营研讨，
> **不构成任何对外的投资建议或披露**；对外使用前须完成脱敏与授权审批。
